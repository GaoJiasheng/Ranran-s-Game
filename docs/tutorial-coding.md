# 编程：玩法和教学规划

编程启蒙（`coding` / `Coding`）。冉冉给小兔排指令，小兔照着一步一步走，把花园里的胡萝卜都吃到。
要学会的不是某一种语言，而是四个想法：**顺序**、**重复**、**起名字再用（绝招）**、**如果**，外加贯穿始终的**捉虫**（先猜、再跑、看哪一步错了、改）。

这份文档前半是定下来的设计（玩法、积木、关卡怎么分、界面、判题），做的人照着做；
后半的课程表和关卡表由做的人细化、补全，改动了设计的地方写明原因。

## 这件事对 6–8 岁的孩子难在哪

1. **先写完再跑**：平时玩游戏是"按一下动一下"，这里要先把整串指令排好，再看小兔自己走。要在脑子里先走一遍。
2. **指令是按顺序一条一条做的**：排错一条，后面全跟着错。孩子会觉得"我都排对了呀"，其实只错了一块。
3. **数数**：走几步、重复几次，差一个就到不了。
4. **看出"一样的一小段"**：重复和绝招的关键是发现路线里反复出现的那一段，这是最大的一道坎。
5. **一个程序管好几种情况**："如果"的意义要靠"同一个程序去走几个不一样的花园"才看得出来。

所以：指令用**上下左右四个箭头**（照屏幕的方向走，不用分小兔的左手右手——转身留给以后）；
每一组只加一个新想法；每一关只比上一关多一点点；跑的时候**正在做的那一块发光**，哪一步出错一眼看得到。

## 花园和规则

花园是格子，最大 7 列 × 6 行。格子上有：

| 记号 | 是什么 | 规则 |
|---|---|---|
| `.` | 草地 | 能走 |
| `#` | 石头 | 走不上去。往石头上走、往花园外面走，都算"撞到了"，程序停在那一步 |
| `C` | 胡萝卜 | 走上去就吃掉 |
| `B` | 小兔出发的地方 | 一关一个 |
| `H` | 小兔的家 | 有家的关：吃完全部胡萝卜再走到家才过关（没吃完路过家不算，接着走） |
| `b` `y` | 蓝花、黄花地砖 | 能走；给「如果」用 |

- 没有家的关，吃到最后一根胡萝卜的那一刻就过关（后面多排的指令不算错）。
- 程序走完了还没过关：没过，告诉她"指令走完了"，停在最后的位置让她看差在哪。
- 一共走了 200 步还没完（只有「一直重复」会这样）：没过，"小兔转晕了"。
- 没过关不扣任何东西，程序原样留着，改了再跑。没有时间限制。
- 「如果」这一组里，一关可以有 2–3 个花园：同一个程序依次到每个花园里跑一遍，每个都过才算过关。

## 积木

| 积木 | 文字写法（关卡数据、测试、调试参数用） | 从哪一组开始 |
|---|---|---|
| ↑ ↓ ← → 走一格 | `U` `D` `L` `R` | 一步一步 |
| 重复 n 次 [ … ]，n 是 2–9 | `3[R U]` | 重复 |
| 绝招 ★、绝招 ◆：先在自己那一栏里排好，主程序里想用几次用几次 | `S` `T`；定义写成 `S=R R U` | 绝招 |
| 如果踩着蓝花 [ … ]、如果踩着黄花 [ … ] | `?b[U]` `?y[D]` | 如果 |
| 一直重复 [ … ]（做到过关为止） | `*[R ?b[U]]` | 如果 |

一整个程序写成一行，各栏用分号隔开：`S 2[S R] ; S=R R U`。

第一版的套法（故意收紧，够教这四个想法，又不会排出看不懂的东西）：

- 「重复」里面可以放箭头、绝招、如果；**不能再放重复**（重复套重复留给以后的新一组）。
- 「绝招」里面可以放箭头、重复、如果；不能放绝招（不能自己叫自己，也不能互相叫）。
- 「如果」里面只能放箭头或绝招，最多两块。
- 「一直重复」只能放在主程序里，而且是最后一块。

每一关规定：有哪些积木可以用、主程序有几格（最外层能放几块）、重复 / 绝招里面有几格。格子数是关卡设计的一部分——
重复那一组的走廊有 6 步长，主程序却只有 2 格，她才会去用「重复」。

**积木数**：程序里所有的积木都算，包括「重复」「如果」的壳和绝招那一栏里的。`2[R U] R` 是 4 块，`S S ; S=R U` 是 4 块。

## 关卡：四组，由易到难

组和关的 id 写进存档，定了不改：组是 `seq` / `loop` / `func` / `cond`，关是 `seq01` … `seq12` 这样。每组 12 关。
学完一组课去玩对应的一组：`basic → 1`，`loop → 2`，`func → 3`，`cond → 4`。通过前两组（一步一步、重复）算"学会了"，后两组是继续往上的挑战。

关有两种：**写程序**（从空的开始）和**捉虫**（程序已经排好了，里面有一处错，把它改对；每组 2–3 关，放在中后段）。

| 组 | 名字 | 新想法 | 12 关怎么一点点变难 |
|---|---|---|---|
| `seq` | 一步一步 | 指令按顺序一条一条做 | 一条直线 2–4 步 → 拐一次弯 → 绕开石头 → **捉虫**（有一个箭头方向错了）→ 两根顺路的胡萝卜 → **捉虫**（少一步 / 多一步）→ 三根胡萝卜，先吃哪根路才短 → 吃完回家（10–12 块） |
| `loop` | 重复 | 一样的事只说一遍 | 长走廊（主程序只有 2 格）→ 两段直线各用一个重复 → 重复加上零散的几步 → 楼梯：重复体里两块 → 更长的楼梯 → **捉虫**（次数差一）→ 重复体三块 → 两个不一样的重复 → **捉虫**（重复体里顺序反了）→ 重复体四块 → 有石头、重复和单步混着用 → 吃完回家 |
| `func` | 绝招 | 给一小段起个名字，到处用 | 同一个小图案出现两次 → 出现三次、中间夹着单步 → **捉虫**（绝招里错一块：改一处，处处都对了）→ 重复里放绝招 → 绝招里放重复 → **捉虫**（主程序里绝招用错了地方）→ 两个绝招 ★ ◆ → 综合 |
| `cond` | 如果 | 一个程序管好几种情况 | 一个花园，重复里放一个「如果踩着蓝花」→ 两个花园、同一个程序 → 三个花园 → **捉虫** → 一直重复 + 如果（不用数步数了）→ 蓝花黄花两种 → **捉虫** → 综合（一直重复、两种花、绝招） |

每一关都要满足（`tools/coding/test.sh` 一关一关查）：

- 参考答案在每个花园里都过关，只用了这一关允许的积木，放得进格子里。
- **用不上新想法就过不了**：重复那一组起，只用箭头的最短走法一定放不进主程序的格子；绝招那一组，不用绝招放不进去；
  如果那一组，不用「如果」不可能每个花园都过（至少两个花园的走法不一样）。
- `par`（"积木不多"这颗星的界限）是**最少**的积木数：用穷举（积木数从少到多把合法程序都试一遍）证明比它少就过不了。
  穷举太大的关可以把 par 定成参考答案的积木数，但要在测试输出里列出来，数量越少越好。
- 捉虫关：给的程序一定过不了；改动一块（换一块、删一块、加一块、改一个次数）就能过，而且改完的积木数不超过 par。
- 同一组里难度不倒退：按（用到几种积木、par、花园大小）大致递增，前后两关不能几乎一样。
- 没有"撞运气也能过"的关：胡乱排满箭头过不了。

**星星**（三颗，`store.recordPuzzle`）：过关 / 没用提示 / 积木不多（用了不超过 par 块；这个数写在屏幕上："用 N 块以内"）。

**提示**（讲道理，分两下）：第一下，猫头鹰说这一组的思路（固定台词、有配音，比如"先找一找，哪几步是一模一样、连着出现好几次的？"；
捉虫关是"点「一步」，一步一步看，小兔是在哪一步走歪的？"）；再点一下，在程序里把"下一块该放什么"用发光的影子标出来
（捉虫关是把错的那一块圈出来）。每点一次只多说一点点，不直接把整串答案摆出来。

## 闯关页面

和别的解谜游戏一样用 `PuzzleSetupView` 选关（每关的小图就是缩小的花园）。点开一关：

- **花园**占屏幕的大头（横屏在左，竖屏在上）。草地用代码画（两种绿交错的圆角格子），小兔、胡萝卜、石头、家、两种花用图片。
- **程序**：主程序一栏；有绝招的关多一栏「绝招 ★」（和「绝招 ◆」）。每一栏画出这一关给的全部格子，空着的格子是浅色的坑。
  「重复」是一块带数字和自己一排格子的大积木：数字点一下弹出 − / + 改次数。「如果」「一直重复」同理。
- **积木盒**：这一关能用的积木，大大的，一排。
- **光标**：只有一个规则——**闪着的那个空位，就是下一块积木落下去的地方**。点积木盒里的一块，它落进光标，光标往后挪一格。
  点任何一个空位（或者两块中间）把光标挪过去；点一块已经放好的积木，它被拿掉，光标停在它原来的位置（于是"换一块"就是点一下、再点新的）。
  拿掉一块带壳的积木（重复、如果）连里面的一起拿掉。一栏满了，积木盒变灰并且轻轻晃一下那一栏。
- **跑**：大按钮「开始」。小兔一步一跳（约 0.45 秒一步，可以切「快」），正在做的那一块积木发光；重复积木上显示"第 2 次"；
  进了绝招，绝招那一栏里的积木接着发光。跑的时候不能改程序；「停」随时停下。
- **一步**：点一下只做一块，用来捉虫。
- 跑完没过关：小兔停在出错的地方（撞石头会晃一下），出错的那一块积木标成红色，猫头鹰说一句（撞到了 / 指令走完了 / 转晕了 / 第二个花园没过），
  按钮变成「再试一次」（小兔回到起点、胡萝卜长回来，程序留着）。
- 多花园的关：花园上面有 1 / 2 / 3 的小页签，跑的时候自动一个一个换，哪个没过停在哪个。
- 过关：`PuzzleDoneOverlay`，detail 写"用了 N 块积木"。
- 工具：提示、清空（要确认，捉虫关是"恢复原样"）、回关卡页。孩子用的页面不滚动，横竖屏都要排得下 7×6 的花园和最长的程序。

## 教学：四组，20 课上下

每课 4–8 步、至少两道题，全部在真的花园和真的积木上动手。组的 id：`basic` / `loop` / `func` / `cond`（封面 `tutor_coding_<id>`）。

题型（`task.type`，都由解释器判，不认写死的答案）：

| 题型 | 她做什么 | 怎么判 |
|---|---|---|
| `build` | 排一个程序让小兔过关 | 跑一遍，过关就对；`rule` 里可以再加条件（必须用到重复、积木不超过几块） |
| `fix` | 程序已经排好了、有一处错，改对 | 改完跑一遍过关 |
| `predict` | 看着排好的程序，点小兔最后会站在哪一格（不让跑） | 解释器算出来的终点 |
| `spot` | 点出程序里错的那一块 | 解释器：就是出错停下的那一块，或者数据里指定的那一块并且验证"换掉它就能过" |
| `choose` | 两三个程序里选能过关的那个 | 每个都跑一遍，正好只有一个能过 |
| `count` | 重复几次才够？选一个数 | 每个数都跑一遍，正好只有一个能过 |

错一次给提示，错两次亮出答案再让她自己做一遍（框架管）。`build` / `fix` 亮答案 = 把参考程序用影子摆出来。

做好的 20 课（id 写进存档；`tools/tutorials/build_coding.py` 生成 `Tutorials/coding.json`，课文都在那个脚本里）：

| 组 | 课（id） | 教什么 | 题型 |
|---|---|---|---|
| **基础** `basic`（指令和顺序） | 小兔听指令 `listen` | 一个箭头走一格；点积木盒排进程序，点「开始」 | build（1 块）、build（3 块）、build（往上） |
| | 排好队再出发 `order` | 程序从第一块做到最后一块，顺序换了结果就不一样 | predict、choose、build |
| | 拐个弯 `turn` | 几个方向接起来走；先用手指比一遍路再排 | predict、build ×2 |
| | 绕开石头 `rock` | 撞到石头程序就停了；绕路要多走几步 | spot（撞在哪一块）、build ×2 |
| | 先数再排 `count` | 每段走几格；两根胡萝卜先吃近的 | count（往右几格）、build（积木不超过 8 块）、build |
| | 捉虫子 `bug` | 程序不对很正常：点「一步」看着它走，找到错的那一块，只改那一块 | spot、fix（换一块）、fix（加一块） |
| **重复** `loop` | 一样的事说一遍 `repeat` | →→→→→ 就是「重复 5 次 →」；点数字改次数 | build（必须用重复）、count |
| | 重复几次 `times` | 数格子定次数；少一次走不到、多一次走过头 | count、predict、fix（改次数） |
| | 重复一小段 `stairs` | 重复里放两块：上楼梯、下楼梯 | predict、build ×2 |
| | 找一样的一段 `pattern` | 在一条长路里找出反复出现的那一段 | choose（哪个重复体对）、build ×2 |
| | 重复再加几步 `mix` | 重复前后还能接单独的箭头、接另一个重复 | predict、build ×2 |
| | 给重复捉虫 `loopbug` | 次数差一、重复里顺序反了、走过头 | spot（次数）、fix ×2 |
| **绝招** `func` | 教小兔一个绝招 `star` | 在星星绝招那一栏排一小段，主程序里放一个 ★ 就做一整段 | predict、build |
| | 绝招用好几次 `reuse` | 同一段路出现好几次 | choose、build ×2 |
| | 绝招和重复 `nest` | 重复里放绝招、绝招里放重复 | predict、build ×2 |
| | 改一处，处处对 `fixstar` | 绝招里错了一块，改好以后每个用到的地方都对了；两个绝招 ★ ◆ | spot、fix、build（必须用 ◆） |
| **如果** `cond` | 如果踩着蓝花 `blue` | 「如果」里面的积木只有踩着蓝花时才做，没踩着就跳过 | predict ×2、build |
| | 一个程序，两个花园 `two` | 蓝花在哪儿不一样，同一个程序都能过 | choose、build ×2（往上、往下） |
| | 一直重复 `forever` | 不用管次数：一直做，过关就停 | predict、build ×2 |
| | 两种花 `yellow` | 蓝花往上、黄花往下，合起来 | predict、fix、build |

一共 58 道题：build 29、predict 11、fix 7、spot 4、choose 4、count 3。每道题都由解释器判，
题里、提示里说到的事实（"小兔撞在最后一块""要走三格""排四块就够"）写在 `task.extra.claim` 里，测试逐条用解释器核对
（`size=N` 还要用穷举证明真的没有更少的排法）。

为什么这样排：

- **每课先读后写**：先做 `predict` / `choose` / `spot`（看懂别人排好的程序），再 `build`。读得懂才写得出，而且读程序的题不用数格子数到头晕。
- **捉虫是每一组的最后一课**，而且从第一组就教：让她从一开始就知道"跑出来不对"是正常的一步，不是做错了。
- **数字小**：基础组的花园不超过 5×4，程序不超过 8 块；重复次数基础阶段不超过 6。
- 每一组的最后一课之后，「去闯关」直接打开对应的那一组关卡。

### 练一练 / 复习

- 每道题写 `drill`，不提上下左右、不提第几格、不提数字（"排一个程序，带小兔吃到胡萝卜！""点一点，小兔最后会站在哪儿？"）。
- 一道题能换四种样子：原样、左右翻、上下翻、都翻。花园、程序里的箭头、答案的格子一起翻（左右翻时 `L`↔`R`，上下翻时 `U`↔`D`）。
  测试把每道题 × 每种样子都判一遍。
- 没写 `drill` 的题按题型有通用说法（`practicePrompts`），同样要配音。

## 配音

- 课文每一句自动进清单。游戏里说的固定台词（撞到了、指令走完了、转晕了、另一个花园没过、每组的思路提示、捉虫的提示、栏满了……）
  写进 `CodingTutorial.kit.fixedLines`，原样抄进 `tools/voice/extra_coding.json`。
- 带数字、会变的话只显示不朗读（"用 6 块以内""第 2 次"）。
- 读音要处理的字（做的人把全部台词过一遍，下面只是已经想到的）：
  "重复"的"重"读 chóng（TTS 一般读对，仍要查）；"一行 / 行不行"避开"行"；"空位、空着"的"空"读 kòng → 换成"控"；
  "得 děi"避开，用"要"；"倒着"读 dào；"朝着、朝右"的"朝"读 cháo；"还 hái 没""只 zhǐ 有"留意。
- 箭头在台词里说"往上、往下、往左、往右"，不说"前进、后退"。

## 做出来的样子（实现说明，和上面的设计不一样的地方都在这里）

代码在 `RanranGame/Games/Coding/`：`Logic/` 只用 Foundation（程序和文字写法 `CodingProgram`、花园 `CodingGarden`、解释器 `CodingRun`、
关卡 `CodingLevelData` / `CodingCatalog`、提示 `CodingHint`、页面尺寸 `CodingLayout`、教学判题 `CodingLessonLogic`、`CodingTutorialKit`），
外面是界面（`CodingStage` 排积木和跑、`CodingBlocksView` 积木和程序、`CodingGardenView` 花园、`CodingPlayView`、`CodingLessonView`、`CodingSetupView`）。
测试和穷举求解器在 `tools/coding/`（`zsh tools/coding/test.sh`；只查关卡 `zsh tools/coding/test.sh levels [id 前缀]`）。

- **「如果」看一下也算一步**：跑的时候「如果」那一块会亮一下，小兔脚下闪一圈（踩着了是绿圈），没踩着就跳过——她看得见"看了、没踩着"。
  "转晕了"的界限：走了 200 步，或者连看花带空转一共 600 下（一直重复里只有「如果」、又一直踩不着花，也要停）。
- **重复的头**：点重复积木上的数字弹出 − / ＋，下面还有一个「拿掉这一块」。因为"点数字改次数"和"点积木拿掉"落在同一块上，
  拿掉重复就放在这个小窗里；「如果」「一直重复」没有数字，点头就直接拿掉（连里面的一起）。
- **光标**：放进带壳的积木以后，光标跳进它里面；壳里面满了，光标自动跳到壳的后面。两块中间有一条看不见的缝（约 0.36 块宽），点它把光标挪过去。
  这一栏满了 / 这一块不能放在这里：积木盒里那一块变灰，点它时那一栏晃一下，猫头鹰说一句（有配音）。
- **积木的大小**：不按她现在排了什么，而是按"每一格都放上最宽的积木"算好，一关之内大小不变；`CodingLayout` 和界面用同一份算法，
  测试在 11 寸 / 13 寸、横竖屏把 48 关和 20 课都算一遍：闯关页积木不小于 62 点、花园格子不小于 50 点、积木盒不小于 60 点；教学里积木不小于 56 点。
- **好几个花园**：页签写"花园 1 / 2 / 3"，跑过的画 ✓ / ✗；跑的时候自动一个一个换，第二个起没过的说"这个花园没过……"。
- **提示**：第一下说这一组的思路（捉虫关说"点「一步」……"）；第二下拿她现在的程序和参考答案一块一块比（`CodingHint`）：
  她少了积木，就在那个空位上摆一块发光的影子（带壳的只摆壳和次数），光标也挪过去；她放错了，就把那一块圈出来。每次只多给一块。
  测试证明：从空程序（捉虫关从给的程序）开始一直照着提示做，一定走到参考答案；捉虫关第一下就圈出有虫子的那一块。
- **星星**：过关 / 没用提示 / 积木不多（不超过 par，屏幕右上角一直写着"现在 N 块""N 块以内有星星"）。
- **捉虫关的个数**：一步一步 2 关、重复 2 关、绝招 3 关、如果 2 关。
- **loop09 改了虫子的种类**：设计里是"重复体里顺序反了"，可是把两块对调要改两块，不满足"改动一块就能过"；
  改成"重复里多了一块"（`3[R D] 3[R U U]` → 删掉一块），顺序反了的虫子放到教学 `loopbug` 课里（那里的 fix 不要求只改一块）。
- **"一直重复"那几关的积木盒里没有「重复」**（cond05–cond12），不然 `9[...]` 和 `*[...]` 一样省，"一直重复"就不是必须的了。
- **新想法用得上**（测试一关一关查）：重复组不用重复、绝招组不用绝招、如果组不用如果，多少块都过不了（穷举到 40 块）；
  同一关里另加的积木（◆、黄花、一直重复），不用它在 par 块以内过不了。
- **难度不倒退**：测试按"par + 1.5 × 用到几种积木 + 2 × (花园数 − 1) + 花园格数 / 12 + 2 × 套了几层"打分，前后两关分数最多只许往回掉 1.6
  （捉虫关和刚学新积木的第一关会稍微低一点），而且相邻两关的花园、答案不能一样。
- **乱排箭头**：主程序每一格都随便放一个箭头（全部组合算出来），能过的机会都在 3% 以下（只有最前面两三关有 1–2%）。
- **教学的 count 题**：小兔吃到最后一根就停，多走的步数不算错，所以"多一次会撞"只在后面还有别的积木时才成立：
  count 题的程序都是"重复 + 后面再走一步"（`#[U] R`、`R# U U`），保证正好只有一个数对。
- **教学的 spot 题**：答案 = 换掉这一块（换成积木盒里的另一块，或者改一个次数）就能过关的那一块；测试要求正好只有一块。
- 课文里的"绝招 ★"念成"星星绝招""菱形"（★ ◆ 不进朗读的句子）。
- **合并时在模拟器里看过以后改的**（11 寸横竖、13 寸竖）：
  - 下面那排按钮：「一步」「慢 / 快」「提示」「清空」四个一样宽（程序那一块宽度的六分之一，最多 100 点），剩下的给「开始」；捉虫关的「清空」叫「重来」。
  - "第 N 次"的小牌骑在重复壳的**右上角**，画在发光的圈上面（原来在头的正上方，会压住"主程序""绝招 ★"这几个字）。
  - 花园的页签贴着花园，一起放在留给花园的那块地方正中。
  - 带壳积木的头（转圈箭头 + 次数、花 + "如果"、∞）只有一个画法 `CodingHeaderGlyph`，程序里、影子里、选程序的题里长得一样。
  - 教学的 spot 题也有「开始」「一步」（找虫子的办法就是一步一步看，提示里也是这么说的）；没有题的演示步骤里，跑的按钮是浅色的，主角是「下一步」。

## 调试参数（都在 `#if DEBUG` 里，读 `UserDefaults.standard`）

- `-route coding`：编程首页；`-pack 2` 选第二组。
- `-codingLevel seq03`：直接打开一关（共用的 `-puzzle seq03` 也行）。
- `-codingProgram "3[R U] R"`：打开时把程序预先排成这样（文字写法同上；放不进这一关的格子就不用）。
